Workspace Control Plane

Discord becomes the project interface

clickityclank is a Discord project/workspace control plane for OpenClaw and Hermes agent teams. It turns a project into a Discord category, and each channel into an expert room with explicit routing, local context, and reviewable generated config.

Instead of hand-editing runtime config for every project, you declare the channel map once: frontend:frontend, backend:backend, qa:qa. clickityclank creates the rooms, records machine-global state, and emits deterministic workspace/config artifacts.

The goal is not fake autonomy. It is boring, inspectable plumbing: every channel has a clear agent target, every generated file has a known path, and every destructive operation can be previewed with --plan, --dry-run, or consumed as --json.

1

Project rooms, not random chats

Categories and channels mirror the way teams actually work: chat, frontend, backend, QA, ops, release, or whatever your manifest declares.

2

Explicit channel→agent routing

No guessing which bot should respond. The channel map is the source of truth for OpenClaw bindings or Hermes route fragments.

3

Runtime-aware context

OpenClaw gets per-channel workspaces and rendered templates. Hermes gets project context plus generated route/config metadata.

4

Safe operational loops

Create, sync, delete, list, show, and doctor are built around deterministic plans, dry-runs, JSON output, and recorded machine-global state.

Channel-native expert rooms

Wire the workspace once. Work in the right room.

Each Discord channel carries intent: #chat can be fast and lightweight, #backend can be deep and tool-heavy, #qa can stay focused on verification. The public UI is Discord; the control plane is generated config you can review.

For OpenClaw, clickityclank patches bindings and scopes safely, creates project-scoped agent IDs when requested, renders AGENTS.md / SOUL.md, and creates per-channel workspaces.

For Hermes, clickityclank writes the project context and route metadata under ~/.clickityclank, then emits a reviewable Hermes config fragment using today's Discord config primitives.

Live default

OpenClaw

Full live provisioning for OpenClaw-backed agent teams.

  • Creates Discord categories and channels.
  • Wires explicit channel→agent bindings and scopes.
  • Supports --project-scoped-agents while reusing shared role bot accounts.
  • Creates per-channel workspaces and renders AGENTS.md / SOUL.md templates.
  • Patches OpenClaw config safely with backups and dry-run plans.
Supported via --runtime hermes

Hermes

Discord workspace creation plus generated Hermes context, routes, and config fragments.

  • Creates Discord categories and channels.
  • Writes project context to ~/.clickityclank/projects/<project>/AGENTS.md.
  • Writes route source-of-truth to ~/.clickityclank/hermes/routes.json.
  • Writes reviewable hermes-config.fragment.yaml.
  • Emits discord.channel_prompts, free_response_channels, no_thread_channels, channel_skill_bindings, skills.external_dirs, and channel_routes metadata.

Get Started

Preview first. Apply when ready.

Use the same command shape for OpenClaw and Hermes. Start with --plan --dry-run, inspect the output, then remove --dry-run when you actually want mutations.

1

Install and initialise templates

Install locally or globally, then seed role templates for the channels you want to create.

2

Validate your environment

Run doctor before mutation. For OpenClaw, check config and bot accounts. For Hermes, review the generated fragment before merging.

3

Choose a runtime

OpenClaw is the default live provisioning path. Add --runtime hermes to generate Hermes project context, routes, and config fragments.

4

Apply deliberately

Drop --dry-run only after reviewing the plan. For Hermes, merge/apply the fragment manually until one-command apply lands.

terminal
# 1. Install and initialize templates npm install -g clickityclank clickityclank init --roles chat,frontend,backend,qa # 2. Validate environment clickityclank doctor # 3a. OpenClaw: live provisioning plan clickityclank project create myapp \ --guild-id $DISCORD_GUILD_ID \ --map frontend:frontend \ --map backend:backend \ --map qa:qa \ --project-scoped-agents \ --plan --dry-run # 3b. Hermes: routes + config fragment plan clickityclank project create myapp \ --runtime hermes \ --guild-id $DISCORD_GUILD_ID \ --repo /path/to/repo \ --map frontend:frontend \ --map backend:backend \ --map qa:qa \ --plan --dry-run # Optional manifest mode shape defaults: mode: balanced maps: - channel: chat agentId: assistant mode: fast - channel: backend agentId: backend mode: deep
